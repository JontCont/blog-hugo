## 前言

開發 [途間旅程規劃網站](https://github.com/JontCont/travel-site) 時，我希望能在行程中查看景點位置、安排路線，也能連到外部地圖查詢導航。隨著需求增加，地圖的做法從一開始的外部連結，慢慢演進成網站內可互動的地圖。

這篇整理專案中的地圖功能、提交歷史與套件取捨，並介紹 React 如何搭配 MapLibre GL JS。以下分析以 **2026-11-16 的主線提交 [`61cb326`](https://github.com/JontCont/travel-site/commit/61cb326)** 為基準；後續程式或外部服務可能會改變。

---

## 一、先認識地圖功能的不同層次

「加入地圖」其實可能包含好幾種不同的功能：

| 層次 | 功能 | 途間目前的方式 |
|------|------|----------------|
| 地圖呈現 | 在網站顯示可縮放、拖曳的地圖 | MapLibre GL JS |
| 地圖資料 | 提供街道、地形或衛星影像 | OpenStreetMap、Esri 等圖磚服務 |
| 行程標記 | 顯示住宿、景點與行程順序 | MapLibre Marker 與行程資料 |
| 點位連線 | 依景點順序畫出示意線 | GeoJSON `LineString` |
| 地點搜尋與導航 | 搜尋地點、查詢步行或其他路線 | 連到高德地圖或 Google Maps |
| 步行距離計算 | 取得實際步行距離與時間 | 後端保留高德 Web 服務 API |

**地圖引擎、圖資與導航服務不是同一件事。** MapLibre 負責顯示地圖；實際的底圖由其他服務提供，而道路導航則需要另外的路線服務。

## 二、React Simple Maps：適合做地圖圖表

[React Simple Maps](https://www.react-simple-maps.io/docs/) 是以 React 元件建立 SVG 地圖的套件，搭配 `d3-geo` 處理地圖投影，也能讀取 GeoJSON 或 TopoJSON。

在專案的第一版站內地圖中，使用了：

- `ComposableMap`：設定地圖投影與範圍。
- `Geographies`、`Geography`：繪製地理區域。
- `ZoomableGroup`：提供縮放與拖曳。
- `Marker`、`Line`：顯示景點與連線。
- `world-atlas/countries-110m.json`：作為世界國家輪廓資料。

概念上像這樣組合：

```jsx
<ComposableMap>
  <ZoomableGroup>
    <Geographies geography={worldData}>
      {({ geographies }) =>
        geographies.map((geo) => (
          <Geography key={geo.rsmKey} geography={geo} />
        ))
      }
    </Geographies>
    <Marker coordinates={[139.6917, 35.6895]}>
      <circle r={4} />
    </Marker>
  </ZoomableGroup>
</ComposableMap>
```

這段只展示元件組合；完整範例還需要匯入元件及準備 `worldData`。當時專案將世界輪廓資料打包進前端，因此顯示這份資料時不必再下載外部圖磚。

### 優點

- 以 React 元件組合 SVG，適合世界地圖、行政區地圖與資料視覺化。
- 可以自行控制顏色、標記、線條與互動事件。
- 如果地理資料隨網站打包，呈現該資料時不必依賴即時圖磚服務。

### 限制

- 套件本身不是街道路網、導航或地點搜尋服務；細節取決於提供的地理資料。
- 專案當時使用的 `countries-110m` 主要呈現世界與國家輪廓，放大後不會憑空出現街道與建築資料。
- SVG 縮放時，標記大小與點擊座標轉換需要額外處理；專案也曾針對標記做反向縮放。

> 這不代表 React Simple Maps 不能畫區域地圖或互動標記；只是當需求變成街道層級的瀏覽時，還需要合適的詳細地理資料與更多自行實作。

## 三、MapLibre GL JS：互動式街道地圖

[MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) 是在瀏覽器顯示互動地圖的開源地圖引擎。它使用 WebGL，支援多種資料來源、圖層、標記、縮放與地圖事件，可以與 React 搭配，但它本身不是 React 元件庫。

### 4.1 引擎與圖磚要分開看

MapLibre 可以使用向量圖磚，也能顯示點陣圖磚。**途間目前的四種底圖使用的是 raster（點陣圖片）圖磚**，不是因為使用 MapLibre 就自動變成向量底圖。

| 專案中的樣式 | 圖資來源 | 用途 |
|--------------|----------|------|
| 標準街道 | OpenStreetMap 標準圖磚 | 一般街道瀏覽 |
| 深色夜間 | Esri Dark Gray 底圖與參考圖層 | 深色地圖顯示 |
| 衛星空照 | Esri World Imagery | 查看空照影像 |
| 暖色街道 | OpenStreetMap HOT 圖磚 | 不同風格的街道圖 |

`setStyle()` 會更換地圖樣式。專案在樣式重新載入後，會再把 GeoJSON 路線圖層加回去，避免切換底圖後連線消失。

### 4.2 優點與限制

**優點：**

- 適合可拖曳、縮放與點選的街道地圖。
- 可搭配不同圖資、樣式、Marker、控制項與 GeoJSON 圖層。
- 專案可依需求切換底圖，並將景點資料疊在地圖上。

**限制：**

- 要自行選擇圖磚來源；地圖引擎不等於免費、無限制的圖資服務。
- 外部圖磚需要網路，也受到服務商的額度、使用條款及可用性影響。
- React 要管理地圖實例、事件監聽與卸載清理；大量 DOM Marker 也可能增加瀏覽器負擔。
- 地圖顯示不會自動產生真實道路導航路線。

> 專案的 `package.json` 目前仍列有 `react-simple-maps`、`world-atlas` 等依賴，但現行 `TripMapPanel` 已改為使用 `maplibre-gl`；依賴仍存在不等於現在的地圖畫面仍由 React Simple Maps 繪製。

## 四、在 React 使用 MapLibre：一個簡單範例

以下示範基本地圖、兩個標記與一條示意連線，不包含導航服務。假設已有使用 Vite 的 React + TypeScript 專案，先安裝：

```console
pnpm add maplibre-gl
```

建立元件：

```tsx
import { useEffect, useRef } from 'react'
import * as maplibregl from 'maplibre-gl'
import 'maplibre-gl/dist/maplibre-gl.css'

export function MapExample() {
  const containerRef = useRef<HTMLDivElement | null>(null)

  useEffect(() => {
    if (!containerRef.current) return

    const points: [number, number][] = [
      [139.7671, 35.6812],
      [139.7967, 35.7148],
    ]

    const map = new maplibregl.Map({
      container: containerRef.current,
      center: points[0],
      zoom: 12,
      style: {
        version: 8,
        sources: {
          osm: {
            type: 'raster',
            tiles: ['https://tile.openstreetmap.org/{z}/{x}/{y}.png'],
            tileSize: 256,
            attribution: '&copy; OpenStreetMap contributors',
          },
        },
        layers: [{ id: 'osm', type: 'raster', source: 'osm' }],
      },
    })

    map.addControl(new maplibregl.NavigationControl(), 'top-right')
    points.forEach((point) => {
      new maplibregl.Marker().setLngLat(point).addTo(map)
    })

    map.on('load', () => {
      map.addSource('trip', {
        type: 'geojson',
        data: {
          type: 'Feature',
          properties: {},
          geometry: { type: 'LineString', coordinates: points },
        },
      })
      map.addLayer({
        id: 'trip-line',
        type: 'line',
        source: 'trip',
        paint: { 'line-color': '#2e6647', 'line-width': 4 },
      })
    })

    return () => map.remove()
  }, [])

  return <div ref={containerRef} style={{ width: '100%', height: 420 }} />
}
```

幾個重點：

1. `useRef` 保存地圖容器，`useEffect` 在元件掛載後建立地圖。
2. 容器要有高度，否則地圖可能看不到；MapLibre 的 CSS 也要匯入。
3. Marker 的座標順序是 `[經度, 緯度]`。
4. `addSource` 提供 GeoJSON 資料，`addLayer` 決定如何繪製。
5. 元件卸載時呼叫 `map.remove()`，清理地圖實例。

範例使用外部 OSM 圖磚，需要網路，也必須遵守圖磚服務政策；不能因為網址不需要 Key，就假設可無限制使用。

### 4.1 途間的 React 整合方式

目前專案在 `TripMapPanel` 中使用 `useRef` 保存地圖與 Marker，並以 `useEffect` 建立、更新與移除地圖。主要功能包含：

- 依日期篩選景點、顯示住宿與行程標記。
- 點選景點後顯示資訊，並可移動畫面到該地點。
- 管理員可以點選地圖，替既有景點設定座標或新增景點。
- 使用 `fitBounds` 或 `flyTo` 調整視野。
- 從景點座標建立 `LineString`，在底圖上畫出順序連線。
- `App` 使用 React `lazy` 載入地圖面板，進入地圖功能時才載入該模組。

這是**直接使用 MapLibre GL JS**，不是透過 React Leaflet 或其他 React 地圖封裝套件。

## 五、高德與 Google Maps：搜尋、導航及步行資訊

### 5.1 外部地圖連結

專案的地圖服務會依旅程國家產生搜尋連結：

- 國家欄位去除前後空白後，以「中國」開頭：使用高德地圖搜尋。
- 其他旅程：使用 Google Maps 搜尋。

這是專案目前的字串判斷規則，不是自動辨識所有國家或地區的通用方法。

行程之間的移動連結則依情況提供：

- 中國旅程：符合座標與 Key 條件時，提供高德 LightMap 步行連結。
- 其他旅程：提供 Google Maps 步行、大眾運輸或開車路線連結。

Google Maps URL 是把使用者導向 Google Maps，不是把 Google Maps JavaScript SDK 嵌入網站。依 [Google 官方文件](https://developers.google.com/maps/documentation/urls/get-started)，Maps URLs 不需要 Google API Key，但不應與其他可能需要 Key 或計費的 Google 地圖 API 混為一談。

### 5.2 高德步行 API

目前 Go 後端保留 `POST /api/walk`，使用 `AMAP_WEB_KEY` 向高德 Web 服務查詢步行距離與時間；高德回應的秒數會換算為分鐘並向上取整。Key 不應放進公開前端程式。

另一個 `AMAP_API_KEY` 則用於專案的高德 LightMap 連結，會提供給已登入的前端使用。兩者用途不同，不能把前端可見的 Key 當作秘密，應依供應商支援的方式限制使用範圍。

目前網站前端**沒有呼叫** `/api/walk` 來自動驗證畫面上的每段移動時間；行程畫面會標示「移動時間尚未驗證」，並提供外部地圖連結。後端有端點，不代表目前 UI 已自動完成所有路線驗證。

### 5.3 地圖上的線不等於實際步行路線

目前 MapLibre 面板把篩選後有座標的景點依順序連成 `LineString`。它只是點與點之間的視覺化連線，不會自動沿道路、避開障礙，也不提供實際步行時間。「全部」模式下，連線甚至可能跨越不同日期。

需要規劃道路路線時，應使用高德、Google Maps 或其他合適的路線服務，並依實際路況與交通方式確認。

## 六、座標格式與使用時要注意的事

### 6.1 經度、緯度的順序

MapLibre 與 GeoJSON 常使用 `[經度, 緯度]`；Google Maps 複製出來的座標則常見 `緯度, 經度`。兩者都是數字，順序錯誤時卻可能畫到完全不同的位置。

目前地圖面板會接受逗號附近的空白；當第二個數值大於 `90`、第一個數值可作為緯度時，才推測是 `緯度, 經度` 並交換。**如果兩個數值的絕對值都不超過 90，程式無法靠數值範圍判斷順序，會按經度在前處理。**

例如 `40.7128, -74.0060` 可能是 Google Maps 的紐約 `緯度, 經度`，但兩個數值都落在緯度範圍內，不能依賴上述規則自動交換。複製座標時應確認來源與順序；地圖面板的解析規則也不代表網站其他座標驗證入口完全相同。

### 6.2 WGS84 與 GCJ-02

座標順序與座標系統是兩件不同的事。專案的行程編輯欄位標示高德 `GCJ-02`，而開放地圖資料通常使用 WGS84 經緯度；高德官方也說明其座標系統與轉換需求。

**交換經緯度順序不會把 GCJ-02 轉成 WGS84。** 專案目前沒有在 MapLibre 畫面自動完成這類座標系統轉換，混用不同來源時可能產生偏移。使用前應確認資料來源、適用地區與服務商的轉換規範。

### 6.3 圖資與使用條款

- OSM 資料可以自由使用，但 OSM 官方圖磚伺服器有獨立的[使用政策](https://operations.osmfoundation.org/policies/tiles/)，需要清楚標示來源，不能批次下載或預抓圖磚供離線使用。
- Esri 與其他圖磚服務各有授權、流量及標示要求；請以實際使用的服務條款為準。
- 圖磚不需要 Key，不代表服務保證免費、無限制或永久可用。較大流量應評估合適的商用服務或自行部署。
- 站內地圖使用外部圖磚時，瀏覽器需要向圖磚服務發出請求；也要考慮網路可用性與隱私需求。

## 七、其他 React 地圖選擇

| 選擇 | 適合情境 | 需要留意 |
|------|----------|----------|
| React Simple Maps | 世界地圖、區域圖表、資料視覺化 | 街道細節取決於資料；導航需要其他服務 |
| MapLibre GL JS | 互動地圖、圖層、可切換地圖樣式 | 需選擇圖資，並在 React 中管理實例與生命週期 |
| React Leaflet | 想使用 React 元件方式整合 Leaflet 地圖 | 是 Leaflet 的 React 封裝；仍需選擇圖磚來源 |
| `@vis.gl/react-maplibre` | 想以 React 元件方式使用 MapLibre | 是 MapLibre 的另一種 React 整合方式，仍需搭配 MapLibre 與圖資 |

後兩者是可供評估的替代方案，**不是這個專案目前採用的套件**。沒有單一套件適合所有需求：如果只是呈現世界統計，SVG 地圖可能比較直接；如果要操作街道圖層，MapLibre 或 Leaflet 可能更合適。

## 八、結語

途間的地圖功能不是只靠一個套件完成：**MapLibre 負責站內地圖、圖磚服務提供底圖，高德與 Google Maps 負責各自的搜尋或路線服務**。從歷史版本可以看出，世界地圖圖表與街道導航是不同需求，適合的工具也不一定相同。

選型時除了看功能，還要一起考慮圖資授權、網路依賴、座標系統、維護成本，以及「示意連線」和「實際導航」之間的差異。
