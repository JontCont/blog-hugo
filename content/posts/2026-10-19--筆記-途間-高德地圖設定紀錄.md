## 前言
途間在中國地區的旅程會用高德地圖，其他地區則用 Google 地圖。本人為了這個設定花了很長時間，高德的 Key 與座標系統有些細節很容易搞混，這篇把踩過的地方整理下來，當作備忘。

---
## 高德地圖怎麼接進來的
途間要處理的是「同一個功能，中國與非中國要走不同的地圖」，所以判斷規則是第一步。程式碼裡的 `isChinaTrip` 很單純：旅程的國家欄位去掉前後空白後，開頭是「中國」就算中國旅程。

判斷後會影響三個地方：
- 地點搜尋：中國旅程用高德的地點搜尋，搜尋範圍是旅程的目的地城市；其他地區用 Google 地圖搜尋。
- 行程路線：中國旅程只顯示高德 LightMap 的步行連結，Google 路線連結不會出現。
- 足跡分頁：中國旅程整個隱藏，因為 Google 時間軸的資料在中國不一定可靠。

---
## 座標一定要是 GCJ-02
這次踩最久的是座標。高德使用 GCJ-02，也就是中國官方加密過的座標系統，跟一般 GPS 拿到的 WGS-84 數字會有偏差，直接貼過去會點錯位置，偏差在幾百公尺以上很常見。

網站的座標欄位寫的是「高德 GCJ-02 座標（經度,緯度）」，格式是經度在前、緯度在後，中間用逗號分開。伺服器會用規則檢查格式，不合法就回傳「請輸入有效的 GCJ-02 經度,緯度」。

不確定座標時，欄位可以直接留空，placeholder 寫的是「尚未確認可留空」。座標不完整時，行程路線不會出現高德連結，也不會查詢距離。

---
## 兩組 Key 的差別
途間用了兩組高德 Key，這是最容易搞混的地方：
- `AMAP_API_KEY`：JavaScript API Key。伺服器會透過 `/api/map-config` 把它交給瀏覽器，用來開 LightMap 的步行導航連結。因為會被瀏覽器看見，README 建議在高德控制台限制可用的網域。
- `AMAP_WEB_KEY`：Web 服務 Key。伺服器用它呼叫 `restapi.amap.com` 的步行路線 API，取得距離與時間。

只設定 JavaScript Key 時，導航連結可以開，但查不到距離。JavaScript Key 不能代替 Web 服務 Key。沒有設定 `AMAP_WEB_KEY` 時，`/api/walk` 會回傳 503 與「尚未設定高德 Web 服務 Key」的訊息。

---
## 步行路線查詢的規則
伺服器端的 `/api/walk` 流程如下：
1. 檢查 `AMAP_WEB_KEY` 是否存在。
2. 檢查起點與終點都是有效的 GCJ-02 座標。
3. 呼叫高德步行路線 API，設定 12 秒逾時。
4. 確認回應狀態為成功，並且有距離與時間。
5. 距離以公尺回傳，時間用 `Math.ceil(秒 / 60)` 換成分鐘，無條件進位。

任何一步失敗，都會回傳錯誤，不會給 0 或直線距離。這是刻意的設計，因為 0 分鐘看起來像「很近」，會誤導行程安排。

---
## 目前的狀態
要老實說，目前的程式狀態是：
- 地點搜尋、LightMap 導航連結、座標格式檢查都已經接上前端。
- `/api/walk` 伺服器端已實作，並有測試（`tests/route-api.test.mjs`）覆蓋。
- 前端還沒有按鈕會呼叫 `/api/walk`，所以目前畫面上的「移動時間尚未驗證」仍然是預設狀態。

也就是說，README 寫的「檢查步行路線」功能還沒完整接到畫面上。之後接上時，這篇會再更新。

---
## 設定時的建議順序
1. 先在高德控制台申請 JavaScript API Key，設定網域限制，填進 `AMAP_API_KEY`。
2. 另外申請 Web 服務 Key，填進 `AMAP_WEB_KEY`，只放在伺服器的環境變數。
3. 把座標一律用 GCJ-02 填寫，不確定就先留空。
4. 啟動後實際點一次 LightMap 連結，確認位置與路線正確。

## 小結
高德的設定重點有三件事：分清楚兩組 Key 的用途、限制前端 Key 的網域、以及把座標統一成 GCJ-02。前兩者設錯通常不會直接報錯，所以設定完成後，一定要實際點一次連結，確認位置與導航都正常。
